# 未登记副本的受限恢复

## 问题与实现

上一轮诊断确认部分维护 PUT 未取得可核验回执，失败来源的目录已经留下未登记的副本。
旧流程再次进入同一任务时重新下载原画、转码，不能复用这些对象。
源文件名、目录存在或声明大小都不足以证明副本可用。

668fcd7 增加单工作器内的受限恢复，沿用现有发现器和流式下载器。
只读取同一 committed 包的 rendition 目录，候选名称绑定原画摘要前缀与目标高度。
逐个完整读取候选，计算完整 SHA256 并校验对象名摘要前缀；核对内嵌的原画完整摘要、
H.264/MP4、目标高度和原清单时长，并完整解码验证。索引记录完整摘要，保留既有算法合同。
只有全部通过且原清单、完成标记与原件仍有效，才最后提交绑定原清单的 rendition 索引。
每个已恢复高度先登记；后续另一高度失败不会丢失已登记副本。没有已验证候选时沿用原转码流程。

目录元数据上限 1MiB；每高度最多尝试两个候选；单候选不超过 64MiB，
每源累计不超过 128MiB，恢复与预留原画下载合计不超过既有 4GiB 下载限额。
仍为单工作器、4MiB/s，恢复媒体阶段总期限 240 秒，ffprobe 45 秒、完整解码 60 秒、输入两线程。
验证失败不登记，不删除未登记文件，不清零失败次数，不扩大编码/上传预算。
长期冷却与公平重试保持；完成事件新增 recovered 数量，上传异常只补充白名单 cause_error，不输出异常文本。

## 隔离验证

先用失败回归证实旧代码不能复用对象、无法在来源变化后阻止恢复登记。
新增测试覆盖复用时不下载原画/编码/上传、480p 登记后 720p 失败保留结果、清单变化与源删除、
总传输预留、候选完整哈希与原画完整哈希合同、大小/期限、取消后收回线程、DAV 属性状态/直接子路径、
候选预算/坏哈希/尝试次数/文件释放。真实隔离 H.264 测试校验原画绑定、高度、时长与损坏数据拒绝。
生产凭据和媒体不进入测试。

完整 scripts/check.sh 通过：Python 1055、Node 215、TS/Vite、架构与仓库门禁。
WSL 完整套件使用 Python 3.13.5；候选维护镜像使用固定 Python 3.11，已验证导入、FFmpeg 与 UID 65532。
没有前端改动、浏览器或真机验收，不将构建成功解释为全库生产播放成功。
