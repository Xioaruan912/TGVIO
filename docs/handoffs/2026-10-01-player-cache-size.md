# 2026-10-01 Player 缓存大小提示与播放排查交接

## 范围

用户要求先检查昨晚 35 秒视频播放约 2 分钟，再将缓存秒数和下载速率改为
已缓存大小 / 文件大小，完成后推送与上传。本轮保留既有原生 TS/Vite、
认证、声音、隐私、三 video 池及 Range；仅上传源码，不切换服务。

## 实现

- net.ts：按浏览器 TimeRanges 并集估算缓存字节，排除 seek 空洞，
  使用实际当前版本大小，缺少数据明确未知。顶栏不再输出秒数或网速；
  估算显式标“约”，不宣称精确下载计数或持久缓存。
- app-header.ts / large.ts / styles/overlay.css：短/长播放共用紧凑两行大小提示。
- settings-view.ts：开关改称“显示缓存进度”，旧 netSpeed 偏好键继续兼容。
- quality.ts：只列出实际版本；缺失旧偏好回退原画时标识准确。
  原画独占的长播放器禁用无效切换；不新增版本或自动转码。
- Node 回归覆盖未知、区间空洞/重叠、当前版本与换源；
  浏览器开启大小提示，检查六视口顶栏、按钮命中及真实隔离播放。
- README / player/AGENTS.md：当前入口及长期估算/清晰度规则同步。

## 排查结论

详见 [只读播放排查](../operations/2026-10-01-player-playback.md)。
高度吻合的候选为 35.22 秒、约 354.5 MiB 的 4K 文件，平均约 84.4 Mbps，
无低清副本；同媒体冷缓存窗口实测 1.84–3.79 MB/s，低于实时消费需求。
原清晰度标签也存在误导，本轮已修正。未确认用户具体视频，不能宣称唯一根因，
未生成低清副本，未声称真实卡顿已经修复。
