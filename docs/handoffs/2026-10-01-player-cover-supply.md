# 2026-10-01 Player 真实封面供给

## 已核对的现状

改版 UI 已绑定 Player cover_url，但生产投影没有封面。生产只读抽样 20 个
有效视频包，20 个均没有 covers.json；这不是全归档覆盖率。
旧生成入口依赖 Bot 数据库，头部读取不是实际 HTTP Range；旧 v1 侧文件没有
原包绑定，Player 也没有消费这类索引，单纯修改卡片不能产生真实图片。

## 本次实现

独立 maintenance worker 从已提交包发现原视频，按有界头尾 Range 生成真实 JPEG，
上传校验后最后提交绑定 package_id、manifest_sha256、media_sha256 的 v2 索引。
Player 校验并投影到已有 media_covers，再通过原有鉴权、版本化 cover API 提供。
原包清单、提交标记、视频、清晰度副本与 Bot 身份保持独立。
封面读取短暂失败保留已有投影；明确不存在时清除。永久删除先删已登记封面，
图片删除失败时保留原视频并准确返回失败。
元数据与 Range 临时错误有界重试三次，持续扫描失败保留检查点并恢复，
错误范围与损坏 JSON 不重试。所有者、资源预算、生命周期、部署与权限合同见 ../development/COVER_SUPPLY.md。

## 验证

scripts/check.sh 完整门禁通过；消费侧初次实现另通过 --browser 验收：
Python 1034 项、Node 215 项、TypeScript/Vite 构建，浏览器 999 项检查；
视口 360、390、430、768、1440，以及 844×390。
新增回归包含绑定/路径/预算/损坏索引、瞬时失败保留、图片优先删除、
真实 HTTP Range 合同、合成尾部 moov 视频实际 FFmpeg 取帧、
实际传输签名与回读 JPEG 哈希、上传验证失败不发布索引、断点续跑与其他条目合并。
自动测试使用隔离媒体/端口，不读取生产口令或私人视频。

## 发布与限制

生产上线与真实抽样结果另写 operations 回执，不能把此文件或测试夹具当作已上线证据。
源文件损坏、全黑/白帧、超过 4GiB、归档 Range 不兼容或 12MiB 预算内缺少
可解码帧可能失败；保留暂无封面，不伪造图片、不改为完整下载。
不覆盖无法验证的旧索引。移动端真机播放未因本次供给修改重新验收。
