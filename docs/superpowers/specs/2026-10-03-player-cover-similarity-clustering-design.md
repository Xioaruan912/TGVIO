## 2. 目标与非目标

**目标**

1. **① 聚在一起**：在墙上按"与首张（或与上一张）相近"重排，使同批/同场景的封面相邻 —— **零新增端点**，客户端就已有瓦片的哈希排序。
2. **③ 和这张像的**：从任意一张封面出发，给出**全库**范围内最像的若干张（有界、需登录）。
3. **② 近似重复检测**：同一套距离阈值下的"几乎一样"提示（不删除、不合并，只标出）。
4. 三者在**没有指纹**时一律表现为"无相似信息"：不报错、不伪造、不把缺哈希当成全等。

**非目标**

- 不做服务端 embedding / 向量库（spec §2 已排除）。
- 不做自动去重、不删任何文件、不改集合成员关系。
- 不改 `covers.json` 契约、不新增迁移（阶段 3 的 `0012` 已够）。
- 不做"跨库相似"或任何把指纹发给第三方的行为。

## 3. 设计

### 3.1 距离与阈值（两种用法共用一个定义）

- 距离 = 两个 16 位 hex 的**汉明距离**（异或后 popcount），范围 0..64。
- **近似重复**：`distance <= 6`（约 10%，dHash 的常用近重复阈值）。
- **相近**：`distance <= 16`（同批/同场景的经验带宽）。
- 两个阈值都定义为**常量并出现在响应/UI 文案里**，不藏在实现细节中；改动它们要改测试。
- 缺哈希（NULL/缺失/坏值）的条目**不参与**任何距离计算，也**不参与**排序末尾的"未知组"（见 3.2）。

### 3.2 ① 聚在一起：客户端排序（无新端点）

- 墙已经分页加载瓦片，每片带 `phash`；排序在**已加载集合内**进行，语义是"把这次看到的排成相似的邻居"。
- 规则：有哈希的瓦片按"与**上一张**的距离"贪心成链（起点为当前首张）；**缺哈希的瓦片按原顺序追加在末尾**，不插入链中（不猜、不伪造）。
- 触发是一个显式开关（工具栏"按相似排序"），**不改变分页请求**（仍然一页一个在途请求、仍受 `MAX_ROWS` 约束）；关掉即恢复原排序。
- 纯函数放在前端独立模块里（`player/web/src/cover-similarity.ts`），可单测：距离、贪心链、缺哈希处理、稳定性。

### 3.3 ③ 和这张像的：有界的服务端端点

- `GET /api/v1/media/{media_id}/similar?limit=&threshold=`
  - 需登录（未登录 401），**与封面同一鉴权**。
  - `limit` 默认 24、上限 60（与瓦片一页同量级）；`threshold` 默认 16、上限 32，且**只允许收紧不允许放宽**（避免"全库都算相似"）。
  - 实现：读取该媒体的 active `phash`；**有界扫描** `media_covers` 的 active 且非 NULL 哈希行（上限 1000 行，与既有 `MAX_ROWS`/`_MAX_ITEMS_OFFSET` 同口径）；按距离升序、距离相同按 `media_id` 升序（确定性）；返回 `{items: [...DTO...], threshold, distance_of_each?}`。
  - **目标媒体没有哈希** → `200 {items: []}`（"无相似信息"，不是 404、不是 500）；媒体不存在 → 404；参数非法 → 400。
  - 扫描超过上限时返回 `{"truncated": true}`，与集合计数的 `count_capped` 同风格：宁可说"我只看了前 1000 条"，不假装全库。
- 前端入口：瓦片上的显式菜单项（不占封面点击）→ 打开一个 `sheet`，里面是同一套瓦片（复用 `buildCoverTile`）+ 距离标注；`sheet` 的焦点陷阱/Escape/原焦点恢复照旧。
- 服务端查询是新的仓储方法（例如 `similar_cover_ids(phash, *, threshold, limit)`），**只读、有界、绑定参数**；`ports.py` 按既有惯例补声明。

### 3.4 ② 近似重复：只标出，不处理

- 在"和这张像的"结果里，`distance <= 6` 的条目带 `duplicate: true` 标记（文案："几乎相同"）。
- 墙上"按相似排序"时，相邻且 `distance <= 6` 的两张不做任何视觉合并，只在密度不高于"中"时给一个细标记（避免密集档位视觉噪声）。
- 不提供"删除重复"动作（spec 非目标：不做自动去重）。

### 3.5 降级与隐私合同

- 缺哈希 / 坏哈希 / 无封面：一律"无相似信息"——不报错、不伪造、不把"两个都缺哈希"当作相似。
- 指纹只发给已登录会话；端点与 DTO 都不新增匿名可读路径。
- 相似列表里**不出现**任何远端路径、凭据或 Bot 侧信息（只复用既有 DTO 字段）。

### 3.6 智能集合（阶段 4 的另一半）：已完成，本文只做核对

- §3.3 的智能集合（条件存 `rules_json`、求值、计数上限、改条件）已在第 2 轮交付并有测试；
- 阶段 4 **不重复实现**；若实施中发现缺口，另开一轮，不在本计划里顺手改。

## 4. 预算、限额与合同

- 新端点：一次请求最多扫 1000 行、返回最多 60 条、单次 SQL 无 JOIN 扇出；超过上限返回 `truncated`。
- 前端：新模块 ≤600 行；`main.ts`/`large.ts` 行数不得增长；不新增封面并发通路（相似 `sheet` 里的瓦片仍走同一个 6 通道队列）。
- 不改分页语义：墙的"按相似排序"是**已加载集合内的重排**，不触发新的分页请求。
- 迁移：无。`covers.json`：无改动。

## 5. 测试与验证口径

**纯函数（前端单测）**：距离的边界（0、64、只差一位）；贪心链对已知哈希序列的精确输出；缺哈希追加末尾且保持原相对顺序；全部缺哈希时输出等于输入。

**端点（Python）**：未登录 401；目标无哈希 → 200 空列表；阈值/上限非法 → 400；确定性（同距离按 media_id）；`limit` 上限；扫描截断 → `truncated: true`；**退役封面行的哈希不得出现在结果里**；结果里每一项都是 active 媒体。

**浏览器回归**：相似 `sheet` 的焦点合同（打开/Escape/原焦点恢复）；相似排序开关切换后**列数与密度档位仍一致**；相似列表里缺哈希条目显示 `missing` 三态之一；在途封面数仍 ≤6。

**生产后验**：新端点需登录（未登录 401）；相似排序不产生额外分页请求（网络面板计数不变）。

## 7. 风险

- **阈值不可移植**：dHash 的阈值是经验值，不同库不同内容会有偏差。缓解：阈值是常量、可收紧不可放宽、UI 文案里带"几乎相同/相近"的定性词而不是承诺精确。
- **全库扫描的诱惑**：实现者容易把 1000 行上限当成"临时限制"而放大。缓解：上限与既有 `MAX_ROWS` 同口径写进合同，超限返回 `truncated`。
- **缺哈希被当成相似**：两个 NULL 相减会得到 0 距离。缓解：距离函数**只接受 16 位 hex**，缺哈希在进入计算前就被排除，测试钉死。
- **"按相似排序"被误当成新分页语义**：合同明确它是已加载集合内的重排，浏览器检查钉住"不产生额外分页请求"。
