# Player 前端观看体验设计

日期：2026-09-23  
状态：待用户审阅  
范围：仅 `player/web` 前端

## 目标

改善移动端 Player 的三个观看问题：切换视频后等待感明显、界面元素遮挡视频、上下滑动不够自然。增加精致但克制的圆弧图形与动画，帮助用户感知加载和播放状态。

## 边界

- 仅修改 `player/web` 中的 TypeScript、HTML 生成逻辑和 CSS。
- 不修改 Player API、Python 服务、缓存实现、Docker、Nginx 或生产环境。
- 前端通过已有接口播放和预热；不改变后端协议。
- 继续保持短视频播放器最多三个复用的 `<video>` 元素，且当前播放优先于预加载。

## 设计

### 播放等待与切换反馈

- 使用现有媒体事件区分加载、首帧就绪、缓冲和播放状态，避免仅凭固定延时展示错误状态。
- 视频切换期间提供轻量圆弧加载动效；首帧显示后平滑淡出，避免黑屏与突然闪现。
- 继续利用相邻视频预热，但不得增加无界请求或让预热抢占当前视频带宽。
- 对慢加载保留清晰、低干扰的等待提示；视频恢复时立即撤掉提示。

### 观看控件

- 播放中的标题、操作按钮和导航使用轻量半透明样式与渐变保护区，减少对画面的覆盖。
- 无操作一段时间后收起非必要控件；点击画面显示控件，暂停时保持必要操作可见。
- 交互控件需保留清楚的点击区域、无障碍名称和安全区适配。
- 加入圆弧/环形视觉作为加载或短暂播放状态反馈，不使用持续旋转的大型装饰遮盖主体。

### 上下滑动

- 以浏览器原生纵向触摸滚动和惯性为基础，保持纵向手势优先；横向拖动进度只在确认横向意图后接管。
- 调整分页吸附与当前页提交时机，减少慢拖时的强制跳页和快速连续滑动时的换片滞后。
- 切换到新页时及时释放非相邻视频，继续复用当前三槽播放器。
- 支持触屏移动端和鼠标/键盘桌面环境，不以自定义拖拽模拟纵向滚动。

## 主要改动区域

- `player/web/src/player.ts`、`preload.ts`：加载状态、就绪状态和有限预热协调。
- `player/web/src/main.ts`、`ui.ts`：状态呈现、控件显隐与用户活动处理。
- `player/web/src/feed.ts`、`gestures.ts`：自然滑动、分页提交和方向判定。
- `player/web/src/styles/feed.css`、`overlay.css`、`shell.css`、`large.css`：圆弧动效、渐变、淡入淡出和移动端安全区布局。

具体文件与事件边界在实现计划阶段按现有代码细化；避免为视觉效果重写播放器结构。

## 验收标准

- 首次加载、正常换片和缓冲期间状态清晰；首帧出现后加载装饰及时消失，无闪烁或残留遮罩。
- 播放时主要观看区域尽量无遮挡；点击后控件能恢复，暂停时不会自动隐藏必要控件。
- 上下慢滑、快速连续滑动与横向拖动进度互不误触；当前视频不会因预热而被延迟。
- 页面保持现有视频元素数量上限和预加载边界；媒体错误、登录态和 API 行为不变。
- 前端 TypeScript/Vite 构建通过；新增或调整的手势/状态逻辑有针对性回归覆盖，并进行移动视口视觉核查。

## 不在本轮处理

- 后端缓存命中、磁盘读写、源 WebDAV 性能与服务端预热。
- 新 API、用户偏好持久化方案、登录机制或生产发布。
